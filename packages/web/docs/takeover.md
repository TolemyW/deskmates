# M1: browser takeover

A workspace is one container with one Chromium and one screen, so taking the browser over is a workspace-level act, not a per-bot one (ADR-0004, design v0.3 §3.3). While a human holds the lock every bot in that workspace gets a wait message from its browser tools.

- **Header controls.** The chat pane reads its thread's `workspaceId` from `getThread` and then `GET /api/workspaces/:id`, which returns the workspace, its bots, the human `browserLock` (never a run's tab lock) and `takeoverScreen`. Free, the header offers **Take over**; held, it says "a human holds the browser" and offers **Hand back** plus an **Open screen** button. `Take over` `POST`s to `/api/workspaces/:id/takeover`, which answers with the lease only; the header then opens a dialog whose `DesktopView` streams the shared screen through the Gateway's screen proxy with a ticket from `/api/workspaces/:id/takeover/open-screen`. No noVNC address or password reaches the page (ADR-0022 amendment 1, C7), and the dialog closes when the hold ends (a `workspace_lock` frame with `null`). `takeoverScreen` is false until the workspace container exists, and then the header says "no screen yet (the workspace container has not started)" and opens nothing. `Hand back` `POST`s to `/api/workspaces/:id/handback`. The controls stay hidden until the workspace view has settled, so the header never offers a button that contradicts the Gateway.
- **`workspace_lock` SSE frame** (`{type: "workspace_lock", workspaceId, browserLock}`): emitted on the takeover and again on the hand back. It carries no `threadId`, so the thread-filtered stream drops it; the pane holds a second, unfiltered subscription for it and two operator tabs agree on who holds the browser without either one refetching. `useWorkspaceLock(workspaceId, api)` (`src/features/chats/use-workspace-lock.ts`) owns the fetch, that subscription and the two actions.
- **Run replay.** A `takeover` ledger event shows its phase (`taken`, `handed_back`) when a human moved the lock, and the tool name plus the wait message the `PreToolUse` hook returned when a run was parked behind one.
