# HTTP API (M0)

All bodies and responses are JSON. Errors are `{code, message, details}` with `code` a `DeskmatesErrorCode` from contracts: `not_found` 404, `validation` 400, `token_rejected` 401, `egress_blocked` 403, `invalid_transition` / `lane_busy` / `browser_held_by_human` / `relay_cap_breached` / `turn_budget_breached` 409, `queue_full` 429 (the queue is full now; retry later), `sandbox_unavailable` 503. A body past a route's size limit never reaches a handler: that is Fastify's own 413, reported as `body_too_large`. Unknown routes are 404 `not_found`. Anything unmapped is 500 `internal` with a fixed `"internal error"` message: the real message (SQLite text, a stack's file paths) goes to the log only, never to a caller that may be running untrusted page content.

Types named below are the `@deskmates/contracts` shapes. `Run` responses are `Run` plus `createdAt`, `config` (the knob configuration recorded in `runs.config_json`), `deliveredSeq` and `error`.

`GET /api/events` is server-sent events. Each frame has `id`, `event` and `data`; `data` is the JSON object below, which always carries `type` and, when the subject belongs to a thread, `threadId`. With `?threadId=` only frames for that thread are sent. A comment line (`: ping`) is written every 15 s.

| `event` | `data` |
|---|---|
| `run_status` | `{type: "run_status", threadId?, run: Run}` on every status change, including `queued` |
| `run_event` | `{type: "run_event", threadId?, event: RunEvent}` for sidecar-pushed and Gateway-originated ledger events alike |
| `thread_message` | `{type: "thread_message", threadId, message: ThreadMessage}` for human, bot and `system` messages |
| `approval` | `{type: "approval", threadId?, approval: Approval}` when a request is posted, matched by a rule, or decided |
| `workspace_lock` | `{type: "workspace_lock", workspaceId, browserLock: BrowserLock \| null}` when a human takes the workspace browser (the lock) or hands it back (`null`), and when a restart releases it. Workspace-wide, so it carries no `threadId` and a `?threadId=` stream does not see it |
| `cost_alert` | `{type: "cost_alert", alert: CostAlert}` when a cost alert rule fires for the window a run's usage landed in (ADR-0018 decision 4); the same run gets a `cost_alert` event. An operator fact with no `threadId`, so only an unfiltered stream delivers it |
| `workspace` | `{type: "workspace", workspaceId, workspace: Workspace}` when the workspace row changed — in M1 that is an egress allowlist edit. Workspace-wide, so no `threadId` |

An open `/api/events` connection is also what the approval broker counts as "a human is online".

## Reopening a held browser screen

`POST /api/workspaces/:id/takeover/open-screen` returns a one-use screen-proxy ticket
(`ScreenAccess`: `{accessId, path: "/api/desktop-stream", protocol, mode: "control"}`) with
`Cache-Control: no-store`, to the session holding the lease only (403 `not_holder` otherwise).
It requires an existing human hold (409 otherwise) and a published screen (503 otherwise),
does not create a container, and neither releases nor renews the hold. It emits no takeover
event. The ticket carries no address or password: the proxy connects to the workspace's
noVNC on loopback, answers its VNC challenge itself and greets the browser with no
authentication. Hand back, lease expiry (the proxy's one-second check), logout or losing the
membership closes the proxied connection at once (ADR-0022 amendment 1, C7). The takeover
response itself is `{lock}` only, also `no-store`.

## Sidecar-facing routes

Under `/internal/runs/:runId/`, authenticated with `Authorization: Bearer <modelAuthToken>` from the `StartRunRequest`. The token must belong to `:runId`, be unexpired and unrevoked, else 401 `token_rejected`. Tokens are revoked when the run reaches a terminal or parked state.

| Method and path | Body | Response |
|---|---|---|
| `POST /internal/runs/:runId/events` | `SidecarEvent[]` (or one `SidecarEvent`) | `{stored: n}`. Every item needs an `attempt` equal to the run's current `attempt`, else 400: a resumed run restarts its `seq` at 1, so redelivery is keyed on `(run, attempt, seq)`. A `(run, attempt, seq)` already stored is a redelivery and is dropped |
| `GET /internal/runs/:runId/egress` | | `EgressAllowlistResponse` `{type: "egress_allowlist", egressAllowlist, updatedAt}` for the workspace of the run's bot, as it is now. The hook re-reads this before a navigation check, so an operator edit reaches a run that started under the old list; `updatedAt` is when the list was last replaced (the workspace's creation until it is) |
| `POST /internal/runs/:runId/browser-lock` | `BrowserLockRequest` | `BrowserLockResponse`. A human lock blocks all tabs. With `tabId`, another run's live lease on that tab returns `granted: false` with `waitMessage`; different tabs proceed. `renew` never creates a missing lease; a tab-specific `release` only drops the matching lease. Calls without tab IDs retain compatibility behavior pending runtime integration |
| `POST /internal/runs/:runId/messages` | `PostMessageRequest` | 201 `{message: ThreadMessage, handoff?: ThreadMessage}`. `thread_post` posts in the run's thread; `message_bot` resolves `to` by name in the caller's workspace and requires the caller's `messageAllowlist`, then posts in a reused pairwise bus thread and queues only the target on the background lane. | `POST /internal/runs/:runId/approvals` | `ApprovalRequest` | 200 `ApprovalResponse` when answered at once (a matching rule, or `defer` because nobody is online), 202 empty when pending and the hook should poll. `riskLevel` must be `L2`, else 400. ## Model proxy

`ANY /v1/*` with the same Bearer token: forwarded to the upstream serving the request's model (ADR-0039, [Model upstreams](model-upstreams.md): `MODEL_BASE_URL` with `MODEL_AUTH_TOKEN`, or a `MODEL_UPSTREAMS` entry with its own token or none) as `Authorization: Bearer`, request body and response body passed through byte for byte (streaming responses included). `x-api-key` is never forwarded. A bad token is 401 `token_rejected` and the upstream is not contacted; an unreachable upstream is 502 `upstream_unavailable`.

The body's `model` must be one of the run's frozen models, `runs.config_json.model` or `cheapModel` (ADR-0023 decision 1, `src/model-proxy/frozen-models.ts`); the check reads the run row, never the prompt. Such a request is forwarded unchanged. When `CLI_SMALL_FAST_MODEL` is set, a request naming that id is forwarded with `model` rewritten to the run's cheap model, and its `model_requests` row keeps the original id in `rewritten_from`. Any other id, or a body with no readable model, is 403 `model_not_selected` with `x-should-retry: false`: the upstream is not contacted, and a `model_requests` row with the id it named and `refusal = 'model_not_selected'` is written. The proxy never retries a model call.
