# Configuration

Read from the environment (`.env` in development) by `src/config.ts`, which composes one reader per domain in `src/config/<domain>.ts` (server, auth, model, sandbox, runs, browser, tenancy, integrations); a new variable goes in its domain's reader and in that domain's section of `.env.example`. `DEFAULT_MODEL`, `CHEAP_MODEL`, `MODEL_BASE_URL`, `MODEL_AUTH_TOKEN` and the production `GATEWAY_OPERATOR_TOKEN` are required. `GATEWAY_BASE_URL` is the URL sandboxes use to reach the sandbox listener (model proxy and internal routes); when empty it is derived from `GATEWAY_BIND` and `GATEWAY_PORT` (`http://host.docker.internal:8080` for Docker on the default configuration). It must never point at `OPERATOR_PORT`. `GATEWAY_DB=:memory:` uses an in-memory database. `WORKSPACE_MEMORY_LIMIT_MB` (default 8192) is the memory ceiling the provider gives a workspace container, and `WORKSPACE_CPU_LIMIT` (default 4 cores, fractions allowed, 0 for none) its CPU ceiling; like `RUN_TIMEOUT_SECONDS` both are knobs recorded in `runs.config_json`. Nothing caps how many sidecar processes a workspace or tenant runs at once (ADR-0022 amendment 5): these two container limits bound them together, and `WORKSPACE_MAX_CONCURRENT_RUNS` and `TENANT_MAX_CONCURRENT_RUNS` are no longer read (`docs/runbooks/multi-tenant.md`). So are the trigger knobs: `CRON_TIMEZONE` (an IANA zone; empty means the Gateway process's own zone — the same expression fires at different instants under different zones, so a result cannot be attributed without it), `WEBHOOK_BODY_MAX_BYTES` (default 65536) and `WEBHOOK_QUEUE_MAX` (default 20). So is `DESKMATES_MAX_TURNS` (default 80), the SDK `maxTurns` of one run, which also rides on every `StartRunRequest`. `RUN_STALL_SECONDS` (default 300, 0 off) is how long a running run may produce no progress event before it shows as `stalled` ([run liveness](run-liveness.md)); it never kills and changes nothing the agent sees, so it is not recorded per run. `RUN_EVENTS_RETENTION_DAYS` (empty or 0: off) is not a run knob: it prunes the events, usage rows and model requests of terminal runs that finished longer ago and keeps the runs, their summaries and Costs; export before you set it ([Run audit and ledger retention](run-audit.md), ADR-0042). `MODEL_PRICES` is not a knob but the price table itself: a JSON array of `{model, inputPerM, outputPerM, cacheReadPerM, cacheCreatePerM, effectiveFrom?}` loaded into the `prices` store at startup and editable afterwards through `PUT /api/prices`; a bad row fails startup. See [Operations (M1)](operations.md). `WEB_DIST_DIR` (empty: no UI served) is the built operator UI the operator listener serves at `/`, and `OPERATOR_BIND` is where that listener binds (`127.0.0.1` by default, `0.0.0.0` for LAN access); see [Operator authentication and listeners](operator-authentication.md). `DESKMATES_RELEASE` (empty: none) is the release tag of the running deployment; `GET /api/config` returns it and the UI sidebar shows it, so an operator can tell which release is live. It is a label, not a knob, and is not recorded per run.

The hybrid search variables (`EMBEDDING_URL`, `EMBEDDING_MODEL`, `RERANK_URL`, `RERANK_MODEL` and four tuning knobs, `config/retrieval.ts`) are described in [Hybrid Knowledge and memory search](hybrid-retrieval.md); all empty keeps FTS5.
