# Grafana image

The analytics surface of run observability (ADR-0046 decision 6): the official Grafana image,
pinned to an exact release and index digest, with the SQLite datasource plugin
(`frser-sqlite-datasource`, exact version in the `Dockerfile`) installed at build time. The
container downloads nothing when it runs: plugin preinstallation, update checks, usage reporting
and the news feed are off.

The image holds no Deskmates configuration. `scripts/stable/stable.sh grafana start` mounts, from
the current release:

| Mount | From | Read-only |
| --- | --- | --- |
| `/etc/grafana/provisioning/datasources` | `observability/grafana/<engine>/provisioning/datasources` | yes |
| `/etc/grafana/provisioning/dashboards` | `observability/grafana/<engine>/provisioning/dashboards` | yes |
| `/var/lib/deskmates-dashboards` | `observability/grafana/<engine>/dashboards` | yes |
| `/var/lib/deskmates-obs` | the directory holding `obs.sqlite` (with its `-wal` and `-shm`) | yes |
| `/var/lib/grafana` | `<stable root>/grafana/data`, Grafana's own state | no |

How it signs people in is `stable.sh` configuration too (ADR-0046 amendment 1): it listens on
`127.0.0.1` under `/analytics/`, signs in whoever `X-WEBAUTH-USER` names from loopback
(`auth.proxy`) as an auto-created Viewer, and has no administrator, password, login form, basic
authentication, anonymous access or Live. The Gateway's `/analytics` relay is that header's only
writer, for the root's own session.

The files under `observability/grafana/` are generated by `packages/observability-dashboards`
and committed; they are not image inputs, so a dashboard change needs no image rebuild. The plugin
is installed under `/opt/deskmates/grafana-plugins` (`GF_PATHS_PLUGINS`) because the state mount
hides `/var/lib/grafana`.

Build it with `scripts/build-grafana-image.sh`: the content-addressed tag
`deskmates/grafana:<arch>-<hash12>` (`node scripts/image-tag.mjs grafana`), plus the alias
`deskmates/grafana:dev` for local work. The build needs Docker Hub and the Grafana plugin catalog
once; `stable.sh grafana init` builds it on the stable host under its content tag only. Operating
it is in [docs/runbooks/grafana.md](../../docs/runbooks/grafana.md).

Checks: `dockerfile.test.mjs` (T0: pins, build-time install, nothing at run time, the plugin the
provisioning names) and `acceptance/grafana-image.container.test.ts` (T2: health under the sub
path, loopback only, signed in only with the header and then as a Viewer, datasource health,
dashboards, a read-only query through the plugin, idempotent start).

Bumping Grafana or the plugin: change the `FROM` tag and its digest
(`docker buildx imagetools inspect grafana/grafana:<tag>`) or `SQLITE_DATASOURCE_VERSION`, build,
and run the T2 file with the new image before releasing it.
