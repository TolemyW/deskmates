# Grafana for run observability

How to run the built-in Grafana (ADR-0046 decision 6 and amendment 1) on the stable host, beside
the Gateway that `stable.sh` operates ([Stable release and deployment](stable-release.md)).
Grafana reads the obs model the Gateway's collector writes to `obs.sqlite`
([run observability](../../packages/gateway/docs/run-observability.md)); it never reads the
ledger. The `sqlite` engine has five dashboards (ADR-0046 amendment 2): Agent runs, with the
failure retrospective, and the four focus areas Model latency, Prompt cache, Approvals and Tool
calls. The retrospective's panels fill only when an embedding service is configured
(`EMBEDDING_URL`, ADR-0041). The provider reads the whole dashboards directory, so a release that
adds or splits a dashboard needs no provisioning change.

Only the root account `admin`, signed in to Deskmates, sees it: Grafana listens on the host
loopback, and the Gateway relays `/analytics/` to it for the root's own session
([analytics relay](../../packages/gateway/docs/analytics-relay.md)). There is no Grafana password
and no other way in.

## What runs

One container, `deskmates-stable-grafana`, on the host network but bound to `127.0.0.1` at
`OBSERVABILITY_GRAFANA_PORT` (default 18700), serving from the sub path `/analytics/`, from the
image `deskmates/grafana:<arch>-<hash12>` built from the current release's `images/grafana`
([image README](../../images/grafana/README.md)). It is not part of the Gateway's systemd unit:
activating, rolling back or restarting the Gateway does not touch it, and it restarts with Docker
(`--restart unless-stopped`).

How it signs people in (amendment 1 decisions 11, 12 and 15):

- `auth.proxy`: whoever the `X-WEBAUTH-USER` header names, from `127.0.0.1` or `::1`, is signed
  in, and created on first use as a Viewer of the main organisation. The Gateway's relay is the
  only client that sets the header, and only ever names `admin`.
- Viewer, because the dashboards and datasource are provisioned from the release and never edited
  in Grafana; a Viewer opens every dashboard and runs its panels, and cannot edit, use Explore or
  administer.
- No initial administrator, no password, no login form, no sign-out menu, no basic
  authentication, no sign-up, no anonymous access, no Grafana Live.

Nothing off the host reaches the port, and neither does a workspace container (it reaches the host
through its network's gateway address, not the loopback). Any process on the host itself could
send the header; the host's own processes can already read the ledger, so that is inside the
Gateway's trust boundary.

Under the stable root:

| Path | What |
| --- | --- |
| `grafana/` | 0700, Grafana's state, owned by the user that runs `stable.sh` |
| `grafana/data/` | Grafana's own database (the `admin` user, preferences); mounted at `/var/lib/grafana` |
| `grafana/logs/build.log` | the last image build |

From the current release, read-only: `observability/grafana/sqlite/` (datasource, dashboard
provider, dashboards), generated by `packages/observability-dashboards`. The directory holding
`obs.sqlite` is mounted read-only and the datasource opens the file with `mode=ro`; the directory
rather than the file because a reader of a WAL database needs its `-wal` and `-shm` files.

## First-time setup

1. Turn the collector on in `shared/.env` and point the relay at Grafana's loopback address:

   ```
   OBSERVABILITY_SINK=sqlite
   OBSERVABILITY_GRAFANA_URL=http://127.0.0.1:18700
   ```

   Restart the Gateway (`systemctl --user restart deskmates-stable-gateway.service`, or the next
   `activate`). `obs.sqlite` appears beside `gateway.sqlite` within a few seconds
   (`OBSERVABILITY_SQLITE_PATH` moves it). `GET /api/observability/status` on the operator port
   shows the watermarks and the newest batch. The Gateway refuses to start when
   `OBSERVABILITY_GRAFANA_URL` is not a loopback `http` origin without a path.
2. Build the image and create the state directory:

   ```
   ~/Data/deskmates-stable/current/scripts/stable/stable.sh grafana init
   ```

   The build is the only step that needs the registries (Docker Hub and the Grafana plugin
   catalog); nothing is downloaded when the container runs. On a host that cannot reach them,
   build the image elsewhere with `scripts/build-grafana-image.sh` from the same release source
   and `docker save` / `docker load` it under the same tag (`node scripts/image-tag.mjs grafana
   --arch amd64` prints it); `init` then reuses it. `init` warns when
   `OBSERVABILITY_GRAFANA_URL` does not name this Grafana.
3. Start it:

   ```
   ~/Data/deskmates-stable/current/scripts/stable/stable.sh grafana start
   ```

   It waits for `/analytics/api/health` on the loopback.
4. Sign in to Deskmates as `admin`. Analytics appears in the navigation and opens
   `<Deskmates address>/analytics/` in a new tab; the run drawer's "Open in Analytics" opens that
   run in the Agent runs dashboard ([web docs](../../packages/web/docs/analytics.md)). Any other
   person gets 403 at `/analytics/`, and no one reaches Grafana's port from another machine.

## Settings

All in `shared/.env`; `grafana start` applies a change by recreating the container.

| Variable | Default | Meaning |
| --- | --- | --- |
| `OBSERVABILITY_SINK` | empty | must be `sqlite`; `grafana init` and `start` refuse anything else |
| `OBSERVABILITY_SQLITE_PATH` | `obs.sqlite` beside the ledger | the obs file; a relative path is relative to `shared/` |
| `OBSERVABILITY_GRAFANA_PORT` | 18700 | Grafana's port on `127.0.0.1` |
| `OBSERVABILITY_GRAFANA_URL` | empty | read by the Gateway: `http://127.0.0.1:<port>`, the relay's upstream; empty hides Analytics |

`OBSERVABILITY_GRAFANA_ANONYMOUS` is retired: `grafana init`, `start` and `status` refuse any value
other than empty or `0` until it is removed. With `OBSERVABILITY_PAYLOADS=full` the obs model
holds tool results of every workspace, which is why only the root sees Grafana. Private chats'
runs never carry payloads or titles into the obs model, whatever the setting, the root's Grafana
included.

## Upgrading, stopping, status

- After `stable.sh activate` of a release, run `stable.sh grafana init` (builds the image again
  only when `images/grafana` changed) and `stable.sh grafana start`: the container is recreated
  with the new release's dashboards and image. Until then it keeps showing the previous release's
  dashboards, which stay on disk. `stable.sh grafana status` says when it lags the current release.
- `stable.sh grafana start` when nothing changed is a no-op.
- `stable.sh grafana stop` removes the container; `grafana/` stays, so `start` brings back the
  same preferences.
- `stable.sh grafana status` reports whether it runs, which release, the port, whether
  `/analytics/api/health` answers, and whether `OBSERVABILITY_GRAFANA_URL` names it.

### Moving from the separate login (decision 6)

A Grafana state directory created before amendment 1 holds `grafana/admin-password`, and its
database holds the user `admin` as Grafana's server administrator, whom the relay's header would
sign in with every right. `grafana init` and `start` refuse it. Run `stable.sh grafana stop`,
remove `grafana/` (only Grafana's own users and preferences; the dashboards come back from the
release), then `grafana init` and `grafana start`, and set `OBSERVABILITY_GRAFANA_URL` as in step 1.

## Troubleshooting

- **Analytics is missing from the navigation:** the Gateway has no `OBSERVABILITY_GRAFANA_URL`,
  or the session is not the root's.
- **`/analytics/` answers 502 `analytics_unavailable`:** Grafana is not running, or
  `OBSERVABILITY_GRAFANA_URL` names another port than `OBSERVABILITY_GRAFANA_PORT`;
  `grafana status` says which.
- **Grafana answers "not signed in" through the relay:** the request did not come from the
  loopback (a Gateway on another host or in a bridged container cannot use this Grafana), or the
  container predates amendment 1; run `grafana start`.
- **Panels say "no such table" or the datasource test fails:** the Gateway has not created
  `obs.sqlite` yet (sink unset, or the Gateway not restarted), or `OBSERVABILITY_SQLITE_PATH`
  changed after `grafana start`; run `grafana start` again.
- **Panels are empty but the file exists:** the collector closes a batch every
  `OBSERVABILITY_BATCH_SECONDS` (default 300); the Pipeline row of Agent runs shows each table's
  last commit and lag, and `GET /api/observability/status` the last error.
- **Port in use:** set `OBSERVABILITY_GRAFANA_PORT`, update `OBSERVABILITY_GRAFANA_URL` to match,
  restart the Gateway and run `grafana start`.
