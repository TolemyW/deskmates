# Reusable QA-agent cases: research and initial design

Date: 2026-09-25  
Status: research and proposed task fixtures; no cases installed or trial run

## Scope and decision

These are tasks for a QA **agent to do QA work**: design an executable regression test from a defect report, reproduce a symptom with evidence, or discover and report a defect in an application. They do not test Deskmates's own control plane. A browser task that merely reaches a page is not a QA outcome. The first realistic pilot is **two real regression-test-writing cases** from Defects4J, followed by **one proposed controlled web-app discovery case** if the runner can protect a hidden oracle. A passing dry run of each fixture and its grader is required before any model comparison. No completion percentage is proposed from these unrun cases.

The [evaluation repair plan](evaluation-repair-plan-2026-09-25.md) requires a versioned fixture outside the bot workspace, independent receipts, and pass/fail/unknown checks. The historical [test strategy](test-strategy-2026-09-20.md) and [deskbench](benchmark-2026-09-20.md) currently exercise the Deskmates harness and task execution; neither establishes QA skill. The case records below use the same evidence discipline while changing the task to what a QA colleague would actually deliver.

## Existing source and feasibility

[Defects4J 3.0.1](https://github.com/rjust/defects4j) directly supplies active, curated `b` (buggy) and `f` (fixed) revisions, issue links, and trigger-test metadata. Its maintainers say a triggering test fails before and passes after the fix and report verification on Java 11; the framework also excludes known broken/flaky tests. Its [setup and CLI documentation](https://github.com/rjust/defects4j/blob/master/README.md) require Java 11, Git, Subversion, Perl and `cpanm`; `init.sh` downloads project repositories and libraries. Its tests run in `America/Los_Angeles`. The harness is [MIT licensed](https://github.com/rjust/defects4j/blob/master/license.txt); the Apache projects have their own [Apache 2.0 license](https://www.apache.org/licenses/LICENSE-2.0). For Deskmates's deny-by-default workspace, prebuild a **Linux amd64 or arm64 image proven on the actual host** with the framework, source repositories, dependencies and both checkouts already installed. The upstream documentation does not promise cross-architecture image parity, so the chosen platform and digest must be pinned and both variants preflighted. No live download in the agent run. The agent sees only its assigned checkout, the task wording, and ordinary project tests/docs; it must not see Defects4J `trigger_tests`, patch files, fixed checkout, issue comments that reveal a fix, or evaluation metadata.

The [TestGenEval authors](https://testgeneval.github.io/) offer a complementary task shape: generating or completing tests on real Python repositories, with compilation, pass rate, coverage and mutation score. It does **not by itself** prove a test catches a specific regression. Use its quality dimensions for a future correctness-test creation track, after selecting and preflighting specific file pairs. Do not substitute its coverage score for the two-variant defect oracle here.

The two Defects4J cases cover regression-test creation from a known behavior. They are not “genuine discovery”: the task names a failing area. The proposed Galaxy case would measure discovery, but only after constructing and validating both app variants. A future TestGenEval case could measure creation of useful tests on a correct codebase without any seeded defect; it needs a different oracle (compilation, passing on baseline, independent coverage/mutation and review for meaningful assertions).

## Fixture, execution, and grading contract

1. **Preflight outside the bot workspace.** Pin Defects4J revision, underlying project commits above, Linux image digest/architecture, Java 11, timezone, dependencies, test command, allowed network policy, and clean initial tree hash. Run unmodified baseline suite on both variants. The evaluator-owned reference regression test must compile and pass on fixed, fail on buggy with the expected assertion or domain exception. A failed checkout, missing package, compiler crash, timeout, network error, unrelated baseline failure, or oracle drift makes the fixture **invalid/unknown**, not a QA detection. Repeat the preflight before a campaign if the image or dependency cache changes.
2. **Agent task.** Give a fresh buggy checkout and the behavior request. Require a changed test file and a reproduction note with input, command or UI steps, expected result, actual result, and evidence IDs. No production-source edits count toward a test-writing result. Preserve the agent's diff, terminal logs, and event trace. Do not accept its “done” claim as evidence.
3. **Independent replay.** Copy only the agent-authored test diff into separately prepared `b` and `f` checkouts. Compile and run that test in both using identical dependencies and commands. Check the test actually runs and contains a live assertion tied to returned behavior, not a disabled/ignored test or an unconditional failure. Verify `f` passes repeatedly and `b` fails repeatedly for the **same relevant assertion or domain exception**. Failure caused by test syntax, import, dependency, fixture setup, timeout, test harness, or network is infrastructure/test validity failure, never “bug found.” Check the rest of the fixed suite for new failures. Run a clean-version negative control and, where feasible, a nearby unrelated input so a broad false positive does not pass. The official triggering test and fixed patch are private evaluator references, not the agent's output.
4. **Verdict fields.** Record separate checks: `artifact_present`, `test_executed`, `fixed_pass`, `buggy_fail_relevant`, `fixed_suite_no_regression`, `clean_control_pass`, `report_reproducible`, `source_untouched`, `no_forbidden_effects`, and `infrastructure_healthy`, each with immutable evidence refs and pass/fail/unknown. Business outcome passes only when the test is valid and discriminates for the intended reason and the reproduction is independently repeatable. A correct test with prohibited source changes can have business pass and constraint fail; a broken environment yields unknown rather than model failure. Track time, turns, and retries separately as diagnostics.
5. **Grader controls.** Reference test passes; an empty/disabled test fails; a test that always throws fails fixed; a syntactically invalid test is test-invalid; missing dependency/network gives unknown; an unrelated failure on buggy is not detection; a broad test that also fails fixed is a false positive; a real focused regression test passes. Remove or swap one log/receipt at a time to verify the intended check changes. The evaluator must store its own verdict and raw command output outside the bot workspace.

For the proposed browser discovery case, grade the independently captured before/after state and operation log, never a screenshot alone. A screenshot helps reproduce the path but cannot prove a committed duplicate. Reset both variants before each attempt; compare the same CSV and require the clean single-row negative control. A report that merely says “import is broken” without records or repeatable steps is not success. A browser outage is unknown; a completed clean app state with no defect evidence is a task fail. This follows the [evaluation repair plan's evidence and unknown rules](evaluation-repair-plan-2026-09-25.md).

## Reuse boundary and next implementation step

Defects4J supplies the two real bugs, commits and official trigger metadata; Deskmates must still build the offline image, author leak-free prompts, store secret grader fixtures, and prove the evaluator controls. The upstream claim of Java 11 reproducibility is evidence for selecting the cases, **not** evidence that they run in Deskmates's current Node/Playwright workspace. They were researched from primary sources; no framework installation, Java compilation, browser run, model run, or source modification was performed for this report. The Galaxy variant is a design proposal and needs code plus its own reference/negative controls before it is eligible for a campaign.
