# Reusable software-development evaluation cases

Date: 2026-09-25. Research only; no task was downloaded, installed, or run on Testbox Linux. These are candidates for an initial **full Deskmates agent** campaign, not measured results. Apply the fixture, independent grader, failure/unknown, and version-freeze rules in [the evaluation repair plan](evaluation-repair-plan-2026-09-25.md). Deskmates's sidecar hosts the Claude Agent SDK inside a shared Linux workspace with shell and filesystem; its current deskbench measures a controlled browser application, not repository repair ([architecture](design-cogbot-thin-core-v0.3-2026-09-20.md), [benchmark](benchmark-2026-09-20.md)).

## Runner and license boundaries

SWE-bench [quickstart](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/quickstart.md) requires Docker and offers one-instance gold evaluation; [CLI documentation](https://github.com/SWE-bench/SWE-bench/blob/main/docs/reference/cli.md) supports selecting instance IDs and records per-instance patch/report/test logs. Its harness code is [MIT licensed](https://github.com/SWE-bench/SWE-bench/blob/main/LICENSE). The Hugging Face Verified page viewed here did **not** display a separate dataset license; do not infer that MIT covers every dataset record or cloned repository. Check each upstream repository license and attribution before redistribution; keeping checkout and tests in a private, ephemeral evaluation volume is the simplest initial route. Public issue pages and gold patches are contamination risks. Block benchmark-specific solution search, omit `hints_text` unless the frozen protocol deliberately includes it, and never mount grader or reference patch into the bot workspace. SWE-bench's published tests are visible in its data, so call them **held out from the bot**, not undisclosed to the world.

Terminal-Bench's repository is [Apache-2.0 licensed](https://github.com/harbor-framework/terminal-bench/blob/main/LICENSE); its [task format guidance](https://github.com/harbor-framework/terminal-bench/blob/main/CONTRIBUTING.md) explicitly separates environment, reference solution and verifier, and runs the verifier in a separate container. Its [README](https://github.com/harbor-framework/terminal-bench) points at the Harbor Hub versioned dataset and asks users to repeat oracle runs because environment flakiness exists. Pin a release/commit and inspect task-specific third-party assets before redistribution. The current `react-lead-form` task's 8-hour limit is a task setting, not a suggested first-campaign budget; a shorter budget is a **new Deskmates protocol** and cannot be compared with published scores. Harbor's Docker verifier must see artifacts from the **actual Deskmates workspace**; this integration has not been demonstrated here.

## Proposed first implementation gate

Freeze a case manifest: source revision and row/task ID, image digest, issue/instruction text, model/config and agent budget, allowed egress, grader version, and evidence paths. Run the official gold/oracle control, a no-change negative control, and a deliberately broken-patch negative control. Then do a single Deskmates attempt per case, with fresh workspace reset and final diff/artifact capture; separately report setup failure, grader failure, business outcome, budget, and tool/approval violations. Only repeated paired attempts on the same frozen cases can support a reliability or strategy-change claim. Linux Docker, image architecture, build/network needs, and verifier portability remain **unverified on Testbox**.
