# Browser evidence and chooser recovery (#65 / #66)

Base: `59ca426403fa2b776b0f928392d3da3d29138b6d` (PR #86). Both issue bodies and
all comments were read on 2026-10-12; neither had comments. The checkout and main
contain no `.agents/skills`. This work changes only the browser evidence / modal
coordination paths, not the other issues in the concurrent repair campaign.

## Root causes and changes

#65: `run-once.ts` took the first 4,000 characters of the entire SDK tool result.
The pinned MCP emits its shared tab inventory before the current page. Long old
redirect URLs therefore displaced page/source evidence. The replacement is a
ledger-only, explicitly incomplete projection: 3,200 characters for page/result
and 600 for metadata, with the entire event excerpt bounded to 4,000. Redaction
runs before slicing, including entity-escaped query parameters. MCP model context
and untrusted wrapping do not change. A bounded artifact stores the redacted
original, including inventory; its own 256 KiB truncation is explicit.

The cache has 128 files per workspace (32 MiB maximum generated bytes), seven-day
age eviction on writes and oldest-first capacity eviction. SHA-256/bytes identify
the recorded artifact; it is mutable workspace data, not an immutable archive.
Download uses the existing tenant/workspace-authenticated ADR-0014 route. The run
view resolves workspace from the run bot's API record, not an untrusted result URL.
Cache failures are recorded and do not fail/retry browser actions. A process crash
can leave the writer lock: cache writes then fail visibly until an operator clears
that lock after checking for an active writer. Expiry is cleanup eligibility, not
a claim that an idle workspace's file is physically deleted at that exact time.

#66: fixed MCP 0.0.82's `defineTabTool` rejects `browser_run_code_unsafe` during
`fileChooser` state. The coordinator used that RPC before *and* after actions and
for focus preparation, so it blocked the tool that resolves the chooser. The
native `browser_tabs` handler is modal-compatible but originally returns only
indices, title and URL; inferring identity from those would be unsafe, especially
with two identical pages. The image now applies a source-fingerprinted shim that
prepends stable CDP ID/live URL/current flag data in that same handler. All tab,
origin and takeover checks use the live identity, and unpatched responses fail
closed. File upload/cancel skips only focus emulation: `FileChooser.setFiles` does
not use page focus. The original upload tool, modal guard, filename checks, normal
PreToolUse approval/egress and origin leases remain unchanged. Ordinary inspection
while a chooser is pending names the completion/cancel tool, not a retry loop.

The shim checks MCP 0.0.82 plus SHA-256 of its exact bundled core before editing;
unknown versions fail the image build. Sidecar and shim must ship together.
There is no timeout increase, target substitution, automatic replay, model-script
allowlist exception, or permission expansion. This implements the same ADR-0004 /
ADR-0007 identity and coordination contract through a modal-compatible read.

## Failure history and untested boundaries

The first raw upload trial failed because its synthetic file was outside the MCP
workspace; the fixture was corrected, not the permission policy. Initial local
checks also found an npm cache path failure and TypeScript exact-optional-property
errors in the download callback wiring; those were corrected before the final
checks. No earlier failed browser/concurrency/model trial is superseded here.

The first PR CI run, [38237465147](https://github.com/TolemyW/deskmates/actions/runs/38237465147),
finished with failure for head `b37e7df2d14e3eeb414284eb0f17088a29c3cadf`.
Static and test shards 1 and 3 passed. Shard 2 had one failure (1,338 tests passed):
`acceptance/t2-lists.test.ts` correctly rejected the new chooser T2 file because
it was absent from both classification lists. The file was then registered in
`t2-full-only.list` with its explicit MCP/build/browser prerequisites; the local
classification suite passed all four tests. This is a corrected test-registration
omission, not a browser-test pass manufactured by increasing timeouts or removing
an oracle. The failed run remains available, and the updated head requires its
own CI result.

The controlled browser used the available host Chromium and pinned MCP, with fake
Gateway lock/origin replies. The complete rebuilt workspace Docker image, real SDK
approval park/resume, graphical native file picker and production multi-bot browser
are not tested here. Real model/API use, merge and deployment are not performed.
In-flight external actions still have the established uncertainty/TOCTOU limits;
this change does not make arbitrary page activity atomic. Full-result artifacts
can expire/evict, fail to save, or be individually truncated, so they are never
reported as complete permanent evidence. No default strategy adoption is claimed.

## Review corrections (2026-10-12)

Code review of PR #94 found the following; the statements above that they
supersede are kept for history.

- Model context. The shim's identity line also reached the model through a
  model-issued `browser_tabs list`, contrary to "MCP model context does not
  change". The mcp-proxy now strips exactly that validated line from every
  `browser_tabs` result it forwards (`stripTabIdentity`), so model context and the
  ledger again carry MCP's own tab list. T1: `proxy.test.ts`.
- Dialogs. Only `browser_file_upload` skipped focus preparation, so a JavaScript
  dialog could not be dismissed: MCP 0.0.82 rejects `browser_run_code_unsafe` in any
  modal state, `dialog` included (`defineTabTool`, checked in the installed
  bundle). Both `clearsModalState` tools (`browser_file_upload`,
  `browser_handle_dialog`) now skip it. In tab-v1 they re-probe identity through
  `browser_tabs list` after lock and origin admission, replacing the identity check
  that focus preparation used to perform.
- Cache. The root check rejected any root below a symlinked ancestor (all macOS
  temporary directories; 2 of 3 unit tests failed there). Only a root that is
  itself a symlink is refused now, and the resolved root is re-checked under the
  lock. Eviction is by bytes against 32 MiB, with a 4,096-file backstop, instead of
  128 files. The writer lock records owner PID and time; a dead owner's lock or one
  older than 30 seconds is broken, and a concurrent writer waits up to 2 seconds
  with backoff. The "operator clears the lock" and "busy writer fails" statements
  above no longer hold.
- The evidence reference shape and the linkable path pattern live in
  `@deskmates/contracts` (`browser-evidence.ts`). The chooser T2 test carries its
  own scenario instead of executing the spike, and the spike scripts overwrite their
  receipts only with `WRITE_RECEIPT=1`.

The T2 scenario was not rerun after these corrections. A local attempt on macOS
with Chrome for Testing 1243 timed out on the first `browser_navigate`, and so did
the unmodified spike on the same host, so that is an environment limit, not a result.
