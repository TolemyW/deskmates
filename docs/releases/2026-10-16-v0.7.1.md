The four T2 failures, none in the image or the hand-over:

- `lan-egress`: the host ran out of Docker default address pools again (31 pools; a separate
  campaign gateway holds 16 workspace networks). Host condition, not a product defect.
- `m0-stack` "the SDK's CLI reached the upstream" (`stream` undefined on the last tool-carrying
  request), `m3-canonical-restoration` (`system` undefined on a restored request) and
  `m4-model-selection` PROXY-01 (a `count_tokens` request reached the upstream): all three
  concern `count_tokens` requests the CLI sends through the proxy with the tool list; whether
  the proxy's forwarding or the tests' expectations are right is not yet decided. Open.

Activated with `SKIP_T2=1` (`.release/t2.skipped`): v0.7.0 could not start a sidecar at all, so
this was strictly better live. No active runs; database backed up to
`backups/20261016T061453Z-v0.7.0-to-v0.7.1`; `/healthz` ok and `/api/config` reports `v0.7.1`.

**Live checks after activation.**

- First run on the taken-over workspaces failed before spawning: the volumes the hand-over
  copied carried no ownership labels, and the provider refuses an unlabelled volume
  ("volume ownership is unverified"). The 15 volumes were recreated by hand with
  `deskmates.managed`, `deskmates.workspace` and `deskmates.tenant` (copied from the legacy
  `<former>.*` labels) and the data copied again from the legacy volumes; the hand-over script
  now does this itself (fixed on `main` after this release).
- Second run spawned the sidecar in the new image, but every model request failed: the CLI's
  first call uses the small-fast model, rewritten to `CHEAP_MODEL=qwen3.8-27b`, which
  `MODEL_UPSTREAMS` routes to the stopped demo services, and the default
  `glm53-flash-public` no longer has a worker on the model gateway (its `/v1/messages` answers
  404 `model_not_found`; `glm53-public`, `deepseek-v4.1-flash-internal`, `qwen38-public` and
  `qwen35-public` answer 200). The model settings were deliberately left unchanged at cutover;
  no run can complete until `DEFAULT_MODEL`, `CHEAP_MODEL` and `MODEL_UPSTREAMS` are repointed.

**Model settings repointed** (owner decision, 15:02 Asia/Shanghai; `shared/.env` backed up as
`.env.bak-20261016T0650Z-before-model-repoint`): `DEFAULT_MODEL=glm53-public`,
`CHEAP_MODEL=qwen38-public`, `MODEL_UPSTREAMS=[]`, `MODEL_PRICES` rewritten with the gateway's
ids (the former rows kept for history). Gateway restarted with zero active runs; `/api/config`
shows both models on the default upstream.

**Interactive runs verified in all four active workspaces.** A chat message asking the bot to
run `ls -la /work` and paste the result was answered correctly in each; the listings show the
directories from before the hand-over, so the volume copy carried the data. The fourth
workspace first failed with "could not find an available, non-overlapping IPv4 address pool":
two workspaces left behind by the day's T2 runs (ids not in the database) were removed by hand,
which freed the pools. One bot posted its reply as the raw JSON summary envelope rather than
the reply text; the other three posted plain text. Unexplained, noted.

**Cheap-model jobs still fail.** Every background job on the cheap model (session title,
activity summary, memory organize) got 500 from the upstream. Captured the CLI's real request
with the Agent SDK against a recording server and replayed it on the model gateway: the
`qwen38-public` backend answers 500 whenever `output_config.effort` is present, which the CLI
sends on every request; without it 200. `glm53-public`, `deepseek-v4.1-flash-internal` and
`qwen35-public` accept the full request. The cheap model therefore needs either an upstream fix
or a different id; owner's call.

**Not yet done live:** cheap-model jobs (above), browser login state in the copied profiles,
the UI in a real browser, and one legacy workspace network still present with a hand-attached
database gateway container (see the v0.7.0 record), whose counterpart under the new prefix now
exists and needs the same container attached.
