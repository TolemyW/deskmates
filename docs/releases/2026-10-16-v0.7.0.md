# v0.7.0

2026-10-16, **v0.7.0 activated** at 13:25 Asia/Shanghai, the first Deskmates release on the
stable host, which until then ran the product under its former name (v0.6.10). Source
`c830afd68cf3b0b8739042f85d023dfa7e64cd3b`: deskmates-private issues #8 to #12 (context and
prompt-cache observability, live run progress and stalled status, bots editable after creation,
runs index with audit marks and retention, group rounds behind `DESKMATES_GROUP_ROUTING=round-v1`),
the OpenAI Agents SDK runtime chosen per bot (ADR-0044), the dual-protocol model upstream,
ADR-0045 proposed, and the hand-over script. The tag was first cut at `7cf745f` without the
runtime merge; the owner had that release and tag deleted and the tag re-cut on `c830afd` after
`feat/openai-runtime` was merged (release workflow run `38852872532`, succeeded).

**Ship and install.** `ship.sh` with `STABLE_HOST=<testbox> LOCAL_BASE=1` and the npm mirror;
the GitHub release manifest download needed one retry. `import-legacy-instance.sh prepare`
copied the legacy `shared/.env` (one `<FORMER>_*` key renamed, same secrets key, operator token
and ports) and installed the `deskmates-stable-gateway` unit. `stable.sh install` rebuilt the
base on the host (`deskmates/workspace-base:amd64-7ba0d4e515d4`, about 22 minutes, the two
`npm install -g` layers downloading at about 150 KB/s from the public registry; the release
workflow's base is `sha256:ef992f01…`, the host's `sha256:32f14189…`), then built
`deskmates/workspace:amd64-11b10dcb93cd` and `deskmates/egress-proxy:amd64-d91326b77b88`.

**Cutover** (owner decision: cut over first, verify after, fix what is found) ran with
`SKIP_T2=1`, recorded in `.release/t2.skipped`. The legacy instance reported zero active runs;
its database was backed up to the legacy root's `backups/20261016T052545Z-handover-to-v0.7.0`,
copied, 31 `bot_sessions` forgotten, 15 volumes (5 workspaces × profile, work, home) copied
under the new names, and `stable.sh activate` backed the imported database up again to
`deskmates-stable/backups/20261016T052551Z-none-to-v0.7.0`. The new Gateway answered
`/healthz` and reported `v0.7.0` on `/api/config`; 33 migrations applied, the last
`202610161000-agent-runtime.sql`; Caddy 18443 to 18381 kept working. Data after the import:
5 workspaces (1 archived), 17 bots, 46 threads, 309 messages, 478 runs, 32 approvals. The
observability collector was repointed to the new database and restarted (schema check passed).
`retire` removed the four legacy workspace container pairs and three of their networks and
disabled the legacy unit; legacy volumes and root are kept for rollback.

**Exceptions and findings.**

- `stable.sh verify` failed in T0/T1: `scripts/public-scan.test.mjs` reads `git ls-files`,
  and the shipped tree is a `git archive` without `.git`. This is the first on-host T0/T1 since
  that step moved into verify (2026-10-13). Fixed on `main` for v0.7.1 (the tracked-file case
  skips outside a git work tree); v0.7.0 has no `t2.passed` receipt.
- The host's Docker default address pools were nearly exhausted (29 of 31 bridge networks in
  use, 16 of them workspace networks of the separate campaign gateway). T2 at six workers failed
  in `networks/create` ("could not find an available, non-overlapping IPv4 address pool") and
  every one of its eight test failures traced to that. See the T2 rerun below.
- One legacy workspace network, `<former>-net-ws_f4d4d62d…`, could not be removed: a database
  gateway container is attached to it by hand so that workspace's bots reach that database.
  The owner detaches it and re-attaches it to the new `deskmates-net-ws_f4d4d62d…` once the
  Gateway creates that network; the hand-over script does not cover hand-attached containers.
- The three model keys that point at the stopped demo services (`CHEAP_MODEL`,
  `MODEL_UPSTREAMS`, `VISION_OPERATION_URL`) were left as they were (owner decision); the
  default model path works.

**T2 rerun** (full scope, two workers, after retire freed three networks, 793 s): 13 files
passed, 26 failed, 1 skipped; 73 tests passed, 48 failed. The network errors were gone; every
remaining failure is one defect: the workspace image links no `openai` package into
`/opt/deskmates/node_modules`, the sidecar imports it at start-up (ADR-0044 completion path),
so no sidecar starts in the v0.7.0 image ("Cannot find package 'openai'" 14 times, sidecar
initialize timeouts 6 times). No run had been triggered on the new instance when this was
found. Fixed on `main` for v0.7.1 with a T0 test that checks the Dockerfile against the
sidecar's dependencies; v0.7.1 replaces v0.7.0 on the host, see its own record.

**Not yet done live:** one run per workspace to check browser login state and `/work` files
survived the volume copy; the UI in a real browser on the stable instance.
