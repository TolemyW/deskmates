# v0.2.2

2026-09-28, v0.2.2 on Testbox. The workstation could not pull the base
from GHCR (one layer retried dozens of times), so the owner approved
`LOCAL_BASE=1`: the host built the same Dockerfile from its build cache in
0.1 s (ID `bffdc561…`; the release workflow's is `61e4c08f…`). Install then
succeeded, but T2 failed 15 of 21 files, for two host reasons:
- Docker ran out of address pools. 13 networks and 24 containers had leaked
  from a 09-23 demo instance, a 09-23 T2 case that failed before cleanup,
  and the 09-26 evaluation campaign, whose runners stopped their Gateways
  without removing workspaces. They were removed on 2026-09-28 (volumes
  kept; inventory in `~/Data/deskmates-stable/cleanup-20260928.txt`), and
  `verify` now caps T2 at `T2_MAX_WORKERS` (default 6).
- Every run failed with `502 egress denied`, with the previous egress image
  as well: Mihomo answers `host.docker.internal` with a fake IP, so the
  proxy's reserved-host fallback (taken only on NXDOMAIN) never fired. The
  proxy now falls back to the bridge address whenever that name resolves to
  a non-private address.
